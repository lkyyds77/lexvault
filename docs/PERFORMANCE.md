# 检索性能

## 实现

0.3.0 起，律知库在加载文档库时一次性建立内存倒排索引：

- 中文文本生成 2～4 字符 n-gram，英文和数字保留词项
- 每个词项保存出现片段与词频
- 查询使用 BM25 类长度归一化评分
- 完整问题短语命中时增加精确匹配权重
- 候选结果使用固定大小 Top-K 选择，不再排序全部候选
- 倒排表使用 `Uint32Array` 压缩内存

导入或删除文档后会自动重建索引。索引只存在于内存，原始文档和持久化知识库格式不变。

## 基准方法

运行：

```powershell
npm run benchmark
```

基准固定生成 20,000 个中文法律条文片段，使用 5 类查询各运行 10 轮，共测量 50 次查询。对比旧版逐片段扫描和新版倒排索引。

一次本机结果：

| 指标 | 旧版全量扫描 | 0.3.0 倒排索引 | 提升 |
|---|---:|---:|---:|
| 中位查询延迟 | 59.59 ms | 1.03 ms | 57.9× |
| P95 查询延迟 | 95.55 ms | 3.19 ms | 30.0× |
| 最大查询延迟 | 139.11 ms | 3.88 ms | 35.8× |

20,000 个片段的索引构建耗时约 475 ms，额外堆内存约 8.6 MB。重复运行中，中位查询提升约 48～90 倍，P95 提升约 28～59 倍。数值会随硬件、Node.js 版本和文本分布变化。

基准中的 5 类查询在旧版和新版上 Top-1 命中率均为 100%，用于确认性能优化没有降低这些固定用例的相关性结果。

实际导入的 36 个司法解释片段中，索引构建约 9.8 ms，连续 1,000 次“船舶油污损害赔偿范围”查询平均约 0.03 ms，并稳定命中第九条。
